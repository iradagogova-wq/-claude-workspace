# Способы сделать мультфильм, не выходя из чата

Всё ниже проверено запуском в этой среде, а не взято из документации.
Дата проверки: август 2026.

---

## Что вообще доступно изнутри чата

| Ресурс | Статус | Проверено |
|---|---|---|
| Gemini API (картинки) | **доступен** | ответ сервера получен |
| ffmpeg 7.0.2 полный | **доступен** | `uv pip install imageio-ffmpeg` |
| Chromium + Playwright | **доступен** | 12 кадров отрендерено |
| Python, Pillow, numpy | доступны | установлены |
| Google Flow / Veo API | **нет** | сайт закрыт, у API нет бесплатного тарифа |
| HuggingFace inference | **нет** | `router` и `api-inference` закрыты |
| fal, replicate, together, groq | **нет** | закрыты прокси |
| GPU | **нет** | 4 CPU, 15 ГБ RAM |

Вывод: генерация **картинок** — есть. Генерация **видео нейросетью** — нет ни одного
доступного пути. Значит движение делается не видео-моделью, а монтажом.
Именно так работала вся рисованная анимация до 2023 года.

---

## Способ 1 · Движение камеры по кадру  ⭐ основной

Кадр от Gemini + наезд, отъезд или панорама. Статичная картинка становится живым планом.
Так снята половина любого мультфильма: фон не двигается, двигается камера.

```
python3 scripts/animate.py ken кадр.png --out клип.mp4 --sec 4 --move in
```

`--move`: `in` наезд · `out` отъезд · `left` `right` панорама · `up` подъём

**Проверено:** 72 кадра, 3 сек. Лимитов нет — работает локально.

---

## Способ 2 · Движение между двумя кадрами  ⭐ основной

Два кадра одного персонажа в разных позах → ffmpeg досочиняет промежуточные
по оптическому потоку. Это классический in-between, только считает машина.

```
python3 scripts/animate.py morph поза1.png поза2.png --out клип.mp4 --sec 2
```

Оба кадра генерируются с одним и тем же листом персонажа в `--ref`, иначе
персонаж сменится посреди движения.

**Проверено:** 33 кадра из 2 картинок.
**Тонкость:** фильтру нужен запас кадров, поэтому каждая картинка внутри
удерживается по 3 кадра. Без этого обхода фильтр молча выдаёт пустой файл.

---

## Способ 3 · Анимация по позам

6–10 поз персонажа → плавное движение на 24 кадрах. Дороже по лимитам Gemini,
но даёт настоящее действие, а не только движение камеры.

```
python3 scripts/animate.py seq папка_с_позами/ --out клип.mp4 --fps 8
```

**Проверено:** 8 поз → 19 сглаженных кадров. Минимум 3 позы, иначе способ 2.

---

## Способ 4 · Рисованная анимация через Chromium  ⭐ без лимитов вообще

Персонаж собирается как SVG, скрипт двигает части тела по кадрам, Chromium
снимает каждый кадр, ffmpeg собирает в видео. Нейросеть не участвует —
значит **никаких дневных лимитов и полная повторяемость**.

Подходит для: морганий, шевеления губ, покачивания, простой ходьбы, титров.
Не подходит для: сложных ракурсов и фотореалистичных фактур.

**Проверено:** 12 кадров SVG-анимации отрендерено и собрано в видео.
**Тонкость:** нужен прямой путь к бинарнику Chromium (`chromium-1194`),
иначе Playwright ищет несуществующую версию и падает.

---

## Способ 5 · Сборка планов в сцену

```
python3 scripts/animate.py join к1.mp4 к2.mp4 к3.mp4 --out сцена.mp4 --fade 0.5
```

**Проверено:** 4 плана → цельная сцена 160 кадров, 6.7 сек, с затуханиями.
CapCut на телефоне больше не обязателен — серия собирается здесь.

---

## Чего этими способами не получить

Честно, чтобы не было разочарования:

- **Сложное действие в одном плане** — драка, танец, бег с разворотом.
  Досочинение кадров работает на плавных переходах, на резких даёт кашу
- **Точное попадание в губы** при длинном диалоге
- **Толпа в движении**

Обход тот же, что в настоящей анимации: короткие планы, монтаж вместо
длинных сцен, реакция вместо действия, звук вместо показа.

---

## Порядок работы

1. `/hero` → лист персонажа, `/gen` рисует его
2. `/episode` → раскадровка
3. `/gen` → кадры серии, все с листом персонажа в `--ref`
4. `/anim` → оживление: способ 1 для планов, способ 2 для действия
5. `/anim join` → сборка серии

Ключ Gemini нужен только на шаге 3. Всё остальное работает и без него.
